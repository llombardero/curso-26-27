## Programación + Entornos de Desarrollo — 1.º DAW — Curso 2026/2027

Documento maestro para utilizar HADA en la formación provisional de equipos antes de la torre de papel Scrum.

Fuente local de referencia:

`Scrum/HADA_Gazteleraz_2019-1.pdf`

## 1. Encaje dentro del ciclo HEXA de H0

- H: S201 presenta el reto H0: diseñar un equipo, ponerlo a prueba con una torre y transferir lo aprendido a MiniJarvis.
- E: S202 utiliza HADA para formular una hipótesis individual de contribución.
- X: S203 combina perfiles, compensa desequilibrios y formaliza funciones, backlog y criterios.
- A: S204 ejecuta dos ciclos de la torre y contrasta la hipótesis con conductas observables.
- A/transferencia: S205 revisa equipo y funciones, acuerda rotaciones y crea el contrato de MiniJarvis.

HADA no sustituye la observación. La torre es la experiencia que permite contrastar y revisar la composición inicial.

---

## 2. Finalidad y límites

HADA ayuda a:

- reconocer preferencias de contribución;
- buscar diversidad en los equipos;
- detectar capacidades menos representadas;
- asignar funciones que compensen desequilibrios;
- abrir una conversación sobre aprendizaje y rotación.

HADA no debe utilizarse para:

- calificar;
- medir inteligencia o competencia profesional;
- emitir diagnósticos de personalidad;
- fijar roles permanentes;
- justificar exclusión;
- publicar clasificaciones individuales;
- sustituir necesidades de accesibilidad u observaciones docentes.

Las puntuaciones individuales son privadas. El alumnado puede compartir tendencias o preferencias, pero no está obligado a mostrar números al equipo.

## 3. Cuestionario HADA

### Instrucciones

En cada fila se leen cuatro afirmaciones. Deben repartirse una sola vez las puntuaciones `4, 3, 2 y 1`:

- 4: corresponde con precisión;
- 3: corresponde bastante;
- 2: corresponde parcialmente;
- 1: corresponde muy poco.

No se repite un valor dentro de la misma fila.

| Fila | Gestor | Puntos | Colaborador | Puntos | Desarrollador | Puntos | Analista | Puntos |
|---|---|:---:|---|:---:|---|:---:|---|:---:|
| A | Soy emprendedor/a. | | Me gusta trabajar con otros. | | Me gusta desarrollar ideas nuevas. | | Me gusta analizar las situaciones. | |
| B | Para mí es importante llegar a la meta rápidamente. | | Me importa que haya un buen ambiente. | | Me gusta ir por caminos nuevos. | | Me gusta trabajar de manera minuciosa. | |
| C | Me gusta asumir responsabilidad. | | No me cuesta acoplarme. | | Me gusta crear propuestas nuevas. | | No me cuesta opinar de manera objetiva. | |
| D | A veces transmito un aire de ser dominante. | | A veces transmito un aire de ser retraído. | | A veces transmito un aire de ser inquieto. | | A veces causo en los demás una impresión de ser demasiado responsable. | |
| E | No me gusta perder el tiempo. | | No me gustan las discusiones. | | No me gusta la rutina. | | No me gusta apurar las cosas. | |
| F | Me importa que haya avances en el equipo. | | Me importa el ambiente en el equipo. | | Me importa la diversidad en el equipo. | | Me gusta que todos trabajen con exactitud. | |

## 5. Diagrama personal

HADA combina dos tensiones:

- orientación a objetivos ↔ orientación a relaciones interpersonales;
- continuidad ↔ cambio.

```text
                         CAMBIO

       GESTOR                         DESARROLLADOR
  objetivos + cambio              relaciones + cambio

OBJETIVOS ----------------------------------- RELACIONES

       ANALISTA                       COLABORADOR
objetivos + continuidad        relaciones + continuidad

                       CONTINUIDAD
```

El alumnado puede trasladar cada suma al diagrama original o registrar los cuatro valores en una tabla equivalente. La representación gráfica no debe convertirse en barrera de acceso.

## 6. Interpretación fiel de los perfiles

### Gestor

Le gusta tomar la iniciativa y puede parecer dominante. Atiende al progreso, asume responsabilidades y se orienta a conclusiones y objetivos. No le gusta perder tiempo o que el trabajo se relaje demasiado.

### Colaborador

Le gusta trabajar con otras personas, adaptarse y cuidar el clima. Suele evitar enfrentamientos y debates y puede parecer retraído.

### Desarrollador

Le gusta crear ideas, propuestas y caminos nuevos. Puede parecer inquieto. Evita rutina y aburrimiento y valora diversidad y creatividad.

### Analista

Trabaja de manera organizada, minuciosa y objetiva. Espera precisión, evita situaciones confusas, es cumplidor y puede transmitir exceso de responsabilidad.

Estas descripciones se presentan como tendencias, no identidades.

## 7. Dimensiones del diagrama

| Perfil | Orientación principal | Dinámica principal |
|---|---|---|
| Gestor | Objetivos | Cambio |
| Colaborador | Relaciones | Continuidad |
| Desarrollador | Relaciones | Cambio |
| Analista | Objetivos | Continuidad |

Un equipo equilibrado necesita atender tanto a objetivos como a relaciones y combinar continuidad con cambio. No necesita cuatro personas “puras” ni puntuaciones idénticas.

## 8. Formación de equipos de tres o cuatro

### Regla de tamaño

Se priorizan equipos de cuatro porque permiten cubrir cuatro focos operativos. Se emplean equipos de tres cuando el número total, la autonomía o las necesidades de apoyo lo aconsejan. No se crea un equipo de cinco solo para resolver un resto salvo circunstancia excepcional documentada.

Para grupos entre 15 y 35:

| Resto al dividir entre 4 | Distribución orientativa |
|---:|---|
| 0 | Todos de 4. |
| 1 | Tres equipos de 3 y el resto de 4. |
| 2 | Dos equipos de 3 y el resto de 4. |
| 3 | Un equipo de 3 y el resto de 4. |

### Orden de decisión docente

1. Determinar participantes reales y ausencias previsibles.
2. Elegir tamaños.
3. Situar apoyos y condiciones de accesibilidad sin publicar motivos.
4. Distribuir presencia relativa de perfiles HADA.
5. Identificar en cada equipo fortalezas y capacidad menos representada.
6. Proponer una función compensatoria.
7. Evitar concentrar todas las necesidades o puntuaciones semejantes.
8. Considerar incompatibilidades pedagógicas conocidas.
9. Registrar la composición como provisional.
10. Revisarla después de la torre.

No se usan como criterios principales amistad, popularidad, género, origen o experiencia previa en programación.

## 10. Funciones sugeridas por el documento HADA

El PDF propone diez funciones posibles:

| Función | Tarea principal |
|---|---|
| Portavoz o director de proyecto | Modera, coordina, mantiene el tema y favorece decisiones y participación. |
| Controlador de tiempo | Vigila tiempos y plazos. |
| Presentador | Presenta conclusiones, memorias y resultados. |
| Responsable de calidad | Favorece trabajo ordenado y exhaustivo y comprueba resultados. |
| Visualizador | Prepara conclusiones escritas para su presentación. |
| Documentador | Completa el diario y administra documentos. |
| Responsable de relaciones exteriores | Mantiene contacto con personas ajenas al equipo. |
| Descubridor | Busca lo inusual y estudia alternativas para aportar ideas. |
| Mediador | Facilita conversación y negociación ante conflictos. |
| Crítico | Actúa como abogado del diablo de manera respetuosa. |

El documento no asigna de forma automática estas funciones a un perfil. Sí ofrece el ejemplo de que, si falta un perfil analista, alguien debe asumir calidad.

## 11. Adaptación operativa para la torre

Para evitar diez cargos simultáneos, H0 agrupa necesidades en cuatro focos:

| Foco | Funciones HADA relacionadas | Responsabilidad en la torre |
|---|---|---|
| Valor y backlog | portavoz, controlador de tiempo | Mantener objetivo, prioridad, tareas y criterio de terminado. |
| Facilitación y tiempo | portavoz, mediador, controlador de tiempo | Facilitar participación, comunicar bloqueos y avisar de hitos. |
| Calidad y pruebas | responsable de calidad, crítico | Recordar restricciones, preparar pruebas, medir y registrar. |
| Evidencias y comunicación | documentador, visualizador, presentador | Registrar decisiones, cambios, aportaciones y review. |

El descubrimiento y prototipado son tareas compartidas por todo el equipo, aunque una tendencia desarrolladora pueda iniciarlas.

Esta tabla es una adaptación educativa de H0, no una tabla literal de Tknika.

## 12. Relación orientativa entre perfil y función

| Tendencia | Puede iniciar con facilidad | Debe poder practicar también |
|---|---|---|
| Gestor | avance, backlog, coordinación temporal | escucha, mediación, revisión |
| Colaborador | facilitación, mediación, presentación | priorización, crítica y decisión |
| Desarrollador | descubrimiento, propuestas y prototipado | cierre, documentación y prueba |
| Analista | calidad, pruebas, documentación y crítica | experimentación y comunicación |

Esta relación es una hipótesis para conversar. El equipo decide funciones atendiendo a fortalezas, capacidades ausentes y objetivos de aprendizaje.

## 13. Protocolo de S203

Cada equipo:

1. comparte voluntariamente aportaciones, no puntuaciones;
2. registra presencia clara, parcial o por compensar de cada tendencia;
3. identifica una fortaleza y una capacidad menos representada;
4. acuerda cuatro funciones y sustitutos;
5. describe una conducta observable para cada función;
6. crea una regla de participación;
7. prepara backlog y definición de terminado de la torre;
8. registra una función que cada persona quiere practicar.

---

## 14. Protocolo de contraste en la torre

Durante S204 se observan hechos:

| Alumno/a | Hace visible función | Participa | Integra ideas | Comunica bloqueo | Usa criterios | Adapta | Explica |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| | | | | | | | |

El docente registra conductas, no etiquetas. La torre utiliza dos ciclos para que la retrospectiva intermedia pueda generar una mejora aplicada.

## 15. Revisión y transferencia

En S205 cada equipo compara:

```text
Hipótesis HADA → conducta observada → aprendizaje → decisión
```

Opciones:

- mantener composición y funciones hasta la siguiente revisión;
- mantener composición y rotar o redefinir funciones;
- solicitar revisión docente por una razón pedagógica concreta.

La caída o altura de la torre no justifican por sí solas cambiar integrantes.

La transferencia a MiniJarvis debe dejar:

- contrato observable;
- funciones iniciales;
- sustitutos;
- fecha o condición de rotación;
- backlog inicial;
- criterios de aceptación;
- evidencias individuales.

---

## 16. Salvaguardas

- No presentar HADA como prueba psicológica validada.
- No usarlo para nota.
- No publicar puntuaciones o perfiles nominales.
- No convertir la puntuación mayor en rol obligatorio.
- No forzar un perfil único si hay empate.
- No interpretar silencio, discapacidad o necesidad de apoyo como falta de capacidad.
- No pedir información médica o familiar.
- No enviar nombres, puntuaciones o conflictos a una IA.
- Revisar los equipos con evidencias y conversaciones privadas.
- Mantener funciones rotatorias.

---

## 17. Criterio de cierre del diagnóstico

- [ ] Cada fila HADA contiene 4, 3, 2 y 1.
- [ ] Cada perfil suma entre 6 y 24.
- [ ] El total es 60.
- [ ] La composición se ha registrado como provisional.
- [ ] Cada equipo identifica capacidad presente y por compensar.
- [ ] Las cuatro funciones están cubiertas.
- [ ] Cada función tiene una conducta observable.
- [ ] La torre está preparada para contrastar la hipótesis.
- [ ] El alumnado sabe que las funciones rotarán.
