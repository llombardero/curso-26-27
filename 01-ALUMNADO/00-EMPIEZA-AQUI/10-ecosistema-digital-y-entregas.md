# Ecosistema digital y entregas



| Evidencia | Fuente canónica | Regla |
|---|---|---|
| Código, historial, tests, diagramas ligados al código y versión evaluada | GitHub desde H1 | No hay copia editable en Drive. Cada hito se identifica con `hN-entrega` o un commit estable. |
| Ejecución, pruebas, decisión técnica, depuración, colección, relación diagrama-código, refactorización, persistencia y seguridad | README del proyecto | Una sección breve sustituye informes separados. |
| Proceso y aprendizaje individual | Diario individual | Solo momentos significativos; aproximadamente investigación, ejecución y cierre, sin cuota rígida. |
| Backlog, decisiones, bloqueos, review, retrospectiva e IA colectiva | Scrum del equipo | Se actualiza cuando cambia el trabajo real, no al acabar cada clase. |
| Fotografías u otra evidencia no-code sin mejor ubicación | Drive | Uso excepcional; H0 puede guardar aquí la torre. |
| Selección personal y comunicación del equipo | Sites | Checkpoints C1 (H1-H3), C2 (H4-H5) y HF (H6-H7 y evolución global). |
| Instrucción, versión entregada y feedback | Moodle | No repite enlaces estables ni el contenido del README. |
| Autoría, comprensión y capacidad de modificar | Defensa | Oral/técnica; no requiere una plantilla escrita paralela. |

## HEXA sin formularios paralelos

| Fase | Evidencia preferente |
|---|---|
| Activar | ticket o reformulación breve del reto |
| Investigar | aprendizaje o prueba significativa; diario solo si aporta valor |
| Idear | decisión significativa en Scrum o equivalente |
| Planificar | backlog y criterio de terminado |
| Ejecutar | código, commits, tests, README y producto |
| Comunicar | demo, review, retrospectiva y defensa |

Una evidencia sólida puede cubrir varias fases. La ausencia de documentos redundantes no se penaliza. Si falta una evidencia, se recupera esa evidencia, no el hito completo.

## Casos especiales

- H0 no usa GitHub, tags ni Sites obligatorios. Conserva HADA privada, ticket individual final, backlog, acuerdos, pruebas de torre, review y retrospectiva.
- La comparación Java-Python se realiza cuando corresponda, pero se registra en diario o se selecciona en portfolio; no crea un informe por hito.
- El uso personal de IA se anota en diario solo si es significativo; el colectivo, en Scrum. H7 intensifica la trazabilidad en README, código/configuración segura, diario/Scrum y defensa.
- Capturas y exportaciones PDF/XLSX solo se solicitan cuando muestran algo no conservable de otra forma o existe una necesidad concreta de conservación.
- La recuperación se activa únicamente para quien tenga una carencia concreta.

## Ruta de trabajo

1. Moodle presenta el reto y registra la entrega oficial.
2. Desde H1, GitHub conserva código, tests, README e historial.
3. Diario y Scrum se actualizan solo cuando sucede algo significativo.
4. Drive recibe únicamente evidencia no-code sin mejor ubicación.
5. Los Sites se actualizan en C1, C2 y HF.
6. La defensa comprueba autoría y comprensión.

Los enlaces estables se registran una vez al inicio y solo se corrigen si cambian. En cada hito se entrega principalmente la versión evaluada.
