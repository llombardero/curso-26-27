# H1 — Entrega digital

## Resultado del hito

Primer MiniJarvis por consola y evidencias del Tema 1.

## Una fuente por evidencia

| Evidencia | Fuente canónica |
|---|---|
| Código, historial y versión | GitHub, tag `h1-entrega` o commit |
| Ejecución, pruebas y decisiones técnicas | README del repositorio |
| Proceso e IA personal | Diario individual, filas H1 |
| Backlog, bloqueos, review, retrospectiva e IA de equipo | Sheet Scrum, pestaña H1 |
| Selección reflexiva individual | Página H1 del Site personal |
| Síntesis del incremento | Página H1 del Site de equipo |
| Índice, fecha, defensa y feedback | Moodle |
| Evidencia no-code excepcional | Drive, solo si no cabe en las fuentes anteriores |

## Entrega en Moodle

Incluye enlaces profundos a:

1. página H1 de tu Site personal;
2. página H1 del Site del equipo;
3. pestaña o filas H1 del Sheet Scrum;
4. repositorio y tag `h1-entrega` o commit;
5. sección de ejecución/pruebas del README;
6. filas H1 de tu diario;
7. Drive solo si existe una evidencia no-code excepcional.

Añade una frase de aportación individual que pueda comprobarse en un commit, una prueba o una fila Scrum.

## No dupliques

- No crees otro portfolio Markdown: el Site personal cumple esa función.
- No crees un archivo separado de ejecución: intégrala en el README.
- No crees un registro de IA paralelo: usa diario o Scrum.
- Moodle enlaza; no almacena una segunda copia salvo petición expresa de cierre.

## Comprobación previa

- [ ] Los enlaces abren con una cuenta no propietaria autorizada.
- [ ] El acceso general está restringido.
- [ ] No hay credenciales ni datos personales.
- [ ] El código está solo en GitHub y la versión está identificada.
- [ ] Cada enlace lleva a la evidencia concreta, no a una portada genérica.
- [ ] Puedo ejecutar, modificar y defender lo entregado.
