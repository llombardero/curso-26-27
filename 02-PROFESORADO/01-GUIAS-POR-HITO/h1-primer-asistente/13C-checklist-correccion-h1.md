## 2. Producto mínimo

- [ ] Existe `Main.java` y el proyecto compila.
- [ ] El programa se ejecuta de forma repetible.
- [ ] Muestra una presentación clara.
- [ ] Lee al menos un dato con `Scanner`.
- [ ] Usa variables con tipos adecuados.
- [ ] Usa al menos una constante con `final`.
- [ ] Realiza una operación sencilla útil.
- [ ] Combina texto y datos en la salida.
- [ ] No incorpora prematuramente menú, bucle principal, colecciones, persistencia o IA real.

## 3. Cobertura del Tema 1

La evidencia puede estar en el producto o en una micropráctica enlazada.

- [ ] Distingue código fuente, JDK, compilación, JVM y ejecución.
- [ ] Localiza clase, `main`, instrucciones y comentarios.
- [ ] Reconoce errores básicos de sintaxis o compilación.
- [ ] Declara, inicializa, asigna y actualiza variables.
- [ ] Reconoce tipos primitivos, `String`, constantes y literales.
- [ ] Predice y comprueba operaciones y precedencia elemental.
- [ ] Lee texto y realiza una conversión sencilla.
- [ ] Explica un error de conversión.
- [ ] Produce y combina valores `boolean`.
- [ ] Prueba las dos ramas de un `if/else` básico.
- [ ] Reconoce anidamiento y el operador `?:` sin exigir dominio avanzado.

## 4. README y pruebas

- [ ] Explica propósito y límites.
- [ ] Indica cómo ejecutar.
- [ ] Incluye transcripción real o enlace profundo a la ejecución.
- [ ] Documenta pruebas relevantes y su resultado.
- [ ] Permite que otra persona ejecute el proyecto.

## 5. Proceso sin duplicidades

- [ ] El diario contiene una fila por checkpoint o evidencia significativa.
- [ ] Las filas incluyen prueba, bloqueo, IA si procede y siguiente paso.
- [ ] Scrum recoge tareas, decisiones y bloqueos del equipo sin actas paralelas.
- [ ] Review y retrospectiva incluyen una acción verificable.
- [ ] No se penaliza la ausencia de documentos que repetirían la misma evidencia.

## 6. Sites

- [ ] El Site personal selecciona y reflexiona; no copia el diario.
- [ ] El Site de equipo resume y enlaza; no copia Scrum.
- [ ] Los enlaces apuntan a evidencias concretas.
- [ ] Los permisos se han probado con una cuenta diferente.

## 7. Uso de IA

- [ ] Si no hubo IA, basta con marcarlo en el diario.
- [ ] Si hubo uso personal, el diario recoge finalidad y validación.
- [ ] Si hubo uso de equipo, está en `REGISTRO_IA_EQUIPO`.
- [ ] La persona explica qué aceptó, qué cambió y cómo lo comprobó.
- [ ] No hay código entregado que no pueda defenderse.

## 8. Defensa

- [ ] Ejecuta el proyecto.
- [ ] Señala el punto de entrada y explica el flujo lineal.
- [ ] Explica variables, tipos, constante, operaciones y `Scanner`.
- [ ] Explica una conversión y una comparación.
- [ ] Predice o prueba las dos ramas de una decisión elemental.
- [ ] Distingue producto principal y microprácticas.
- [ ] Realiza una modificación pequeña sin romper el programa.
- [ ] Justifica cualquier uso de IA.
