# Matriz de plataformas y evidencias

| Elemento | Ubicación principal | Moodle recibe | No debe ocurrir |
|---|---|---|---|
| Reto, instrucciones y rúbrica | Moodle | No aplica | Mantener instrucciones contradictorias en varias plataformas. |
| Código y README técnico | GitHub desde H1 | URL + commit o tag | Copia editable paralela en Drive. |
| Evidencia de ejecución | Drive o GitHub | URL concreta + copia cerrada si se evalúa | Entregar solo una carpeta general. |
| Diario individual | Google Sheets personal | URL restringida + extracto/exportación del hito | Usarlo como portfolio público. |
| Backlog, sprint y bloqueos | Sheet Scrum del equipo | URL del libro | Copiar el backlog manualmente en Moodle. |
| Decisiones, review y retrospectiva | Sheet Scrum del equipo | URL + fila/hoja identificada | Repetir el mismo texto en tres lugares. |
| Evidencias seleccionadas personales | Site personal | URL de la página del hito | Publicar datos personales o calificaciones. |
| Producto y proceso de equipo | Site del equipo | URL de la página del hito | Usarlo como repositorio de código. |
| Calificación y feedback | Moodle | No aplica | Guardarlo en Sites o carpetas compartidas. |
| Puntuaciones HADA y observaciones privadas | Registro docente privado | Nada | Publicarlas al equipo o al grupo. |

## Regla de enlace profundo

Cada entrega debe apuntar a la página, archivo, pestaña o commit concreto. No basta con enlazar la raíz de Drive, Sites o GitHub.
