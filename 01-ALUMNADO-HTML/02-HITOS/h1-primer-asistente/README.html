H1 — Primer asistente por consola

Para qué sirve esta carpeta

Esta carpeta reúne los materiales del alumnado para H1.

El reto consiste en construir la primera versión técnica de MiniJarvis: un programa Java pequeño, ejecutable por consola y suficientemente sencillo como para poder comprenderlo, comprobarlo, modificarlo y explicarlo.

H1 establece también una forma de trabajo que se reutilizará en los siguientes hitos.

Producto técnico

La evidencia principal de H1 es el propio programa.

Una estructura mínima es:

h1-primer-asistente/
├── README.md
└── src/
    └── Main.java

El proyecto del alumnado debe permitir:

abrir
  ↓
ejecutar
  ↓
observar
  ↓
comprobar
  ↓
modificar
  ↓
volver a ejecutar
  ↓
explicar

No es necesario demostrar el funcionamiento mediante capturas rutinarias si puede reproducirse ejecutando el programa.

El README del proyecto del alumnado no es este archivo. Este archivo pertenece a los materiales del curso; cada proyecto H1 tendrá su propio README técnico.

Qué necesitas conservar Dónde

El Site personal no se actualiza por cada hito. Se utiliza para seleccionar evidencias en los cierres periódicos establecidos.

HEXA en H1

H1 recorre un ciclo HEXA completo de seis fases.

Equipos es una dimensión transversal durante todo el hito, no una fase anterior o posterior a las demás.

Equipos — transversal durante todo H1

Activar
   ↓
Investigar
   ↓
Idear
   ↓
Planificar
   ↓
Ejecutar
   ↓
Comunicar

Equipos — dimensión transversal

Durante todas las fases, el equipo organiza tareas, colaboración, decisiones y bloqueos cuando sean significativos.

Activar

Comprender el reto y delimitar qué entra y qué no entra en H1.

Investigar

Aprender los conceptos necesarios para poder construirlo.

Idear

Decidir cómo será la primera versión.

Planificar

Convertir la solución en tareas manejables dentro de Scrum.

Ejecutar

Construir, ejecutar, comprobar, corregir y mejorar.

Comunicar

Mostrar el producto y explicar decisiones, código y aprendizaje.

Una misma evidencia puede servir para varias fases.

HEXA no significa crear un documento por fase ni otro documento para Equipos.

Qué debe sobrevivir al terminar H1

Al cerrar el hito deben poder localizarse:

  • una versión identificable del código;
  • un programa que pueda ejecutarse;
  • un README técnico suficiente;
  • las tareas y decisiones significativas del equipo;
  • los aprendizajes individuales significativos, si los hubo;
  • la trazabilidad de IA significativa, si existió;
  • la posibilidad de realizar una demo y una defensa sobre el producto real.

Qué no necesitas crear

H1 no requiere de forma rutinaria:

  • un documento por sesión;
  • un informe de ejecución;
  • capturas de cada prueba;
  • una tabla independiente de pruebas;
  • un informe de errores;
  • un documento para la defensa;
  • un registro independiente de IA;
  • un portfolio específico de H1;
  • copias del código o del README en Drive;
  • versiones PDF del README.

Si algo ya existe en su fuente canónica, se enlaza o se comprueba allí.

Orden recomendado

Para trabajar H1:

1. Consulta la ficha 13B.
2. Sigue las sesiones H1.1-H1.10.
3. Utiliza los capítulos 01 y 02 del libro cuando necesites estudiar conceptos.
4. Construye y comprueba MiniJarvis progresivamente.
5. Mantén Scrum y el README solo cuando haya algo significativo que conservar.
6. Revisa ENTREGA-DIGITAL al preparar el cierre.
7. Ejecuta y defiende la versión real.
